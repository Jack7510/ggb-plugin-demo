## 可直接口述的讲解稿

我们用这个 GeoGebra 教学工程，说明一个插件的三个关键部分：Skill、工具和契约。
宿主 Agent 负责理解文字，沿用宿主已有的推理能力，不需要额外的模型服务。

先看 Skill。它告诉 Agent 什么时候使用这项能力，怎样提取要求、编写请求、调用
工具和阅读报告。正文保持通用，三角形这样的具体配方放在示例中。Skill 可以指导
操作，但不能授予数学检查通过的结论。

再看契约。这里保存原题，也单独保存初始坐标等演示选择。请求不仅有原生命令，
还有声明输出、逐条要求、检查与交互样本。以中点为例，M 恰好位于坐标 (3,0)，
并不说明它由 A、B 驱动。我们同时核对原生依赖与中点关系。输入预检只确认结构和
执行边界，数学条件必须交给真实引擎。

工具把这些声明变成实际执行。CLI 通过 Playwright 驱动固定的官方 GeoGebra，
采集对象类型、定义状态、依赖、坐标和样式。导出以后，它关闭原上下文，在新的空
applet 中重新读取磁盘 GGB。每个拖动样本也独立加载，再用真实鼠标操作，记录前后
事实和截图。所有必需检查以及资源关闭通过后，工具才提交正式交付目录。

最后看结果。报告可以追溯到请求中的要求，清单可以核对文件摘要，预览加载同一份
GGB。ready 表示窗口可交互，closed 和清理记录才说明资源已经退出。任何必需条件
失败或未验证，都不能由 Agent 自行改写成成功。

目前独立 CLI、真实引擎构造、重载和拖动已有案例证据。Skill 完成了编写与静态检查，
宿主发现、独立安装和发布仍未验收，构图取消协议也还没有完成。有限样本通过不能
当作一般数学证明。这个工程可以迁移的方法，是让 Skill 指导调用，让契约明确检查，
让工具依据真实引擎证据交付。

## 补录入口与片尾

环境准备使用 [README](../README.md#环境与安装)。命令从
[CLI 契约](demo-contract.md#命令与输出)取用，不从旧录制计划猜测可用功能。

在仓库根、已完成环境准备和构建的前提下，完整案例的入口是：

```sh
node dist/src/cli.js check --request examples/triangle.json
node dist/src/cli.js build --request examples/triangle.json
```

预览使用契约中的 `preview --delivery`，传入本次 build 返回的实际路径。
三角形静态子案例与固定技术实验不能代替完整案例的拖动验收。

片尾链接 [README](../README.md)、[契约](demo-contract.md) 和
[验收记录](acceptance.md)。测试数字与产物路径只引用验收记录中注明日期的实际运行，
不为拍摄重复运行已有充分证据的检查。原[录制脚本](recording-script.md)包含未来
安装和发布计划；本片只总结当前完成部分，不照读其中尚未实现阶段的完成旁白。
